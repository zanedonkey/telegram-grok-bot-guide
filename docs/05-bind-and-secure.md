# 05 · 绑定和权限

[上一步](04-forward-and-reply.md) · [返回首页](../README.md) · [下一步](06-run-and-recover.md)

## 第六步：确认自己的身份

1. 启动处于“未绑定”状态的桥接程序。
2. 向自己的机器人发送 `/start`。
3. 程序仅登记待绑定请求，不执行普通任务。
4. 在可信管理入口核对该请求确实来自自己的账号。
5. 明确确认后，保存允许的数字 `from.id` 和 `chat.id`。
6. 从已绑定账号再发送一条无副作用任务，检查结果。

不要公开数字身份。不要用用户名作为唯一鉴权信息，也不要把最先发送 `/start` 的用户自动设为管理员。

## 第七步：权限边界

- 仅接受已绑定账号的 private 消息。
- 未授权请求忽略，不进入任务入口。
- 已绑定状态不得被新的 `/start` 替换；换绑需可信入口确认。
- Telegram 消息不能覆盖系统规则、改绑定或读取密钥。
- 删除重要数据、转账、公开发布等操作按平台授权规则处理。
- 身份限制必须落在程序和平台机制中，提示词只是补充。
- 回复端校验目标，不能按外部文本指定任意收件人。
- 凭据、绑定文件、日志和备份保留在部署环境，不上传仓库。

成功标准：自己的私聊可处理；第二个账号和群消息无法触发；没有第二个账号时，将拒绝访问检查标记为未实测。

反馈问题前阅读 [隐私说明](../PRIVACY.md)。
