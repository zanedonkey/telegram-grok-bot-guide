# 06 · 运行和恢复

## 第八步：选择后台运行方式

让生成程序的助手交付适合实际环境的启动、停止、重启、状态检查方式。文档中的示意名称不能当作已存在的脚本。

| 环境 | 建议检查 |
| --- | --- |
| Linux VPS | 服务管理器、单实例、重启恢复、文件权限 |
| Windows 常开设备 | 任务计划程序或受管理服务、休眠、用户权限 |
| 平台云端电脑 | 当前平台允许的运行机制、生命周期和文件保留规则 |

停止时保存状态；重启时沿用队列和接收进度。不要在每次启动时盲目清空消息或绑定状态。

若当前平台提供健康检查 Routine，确认频率、费用和授权边界后再启用。正常状态保持安静，仅在故障、恢复或需要人工处理时通知。

## 备份

备份应覆盖程序、必要状态和恢复说明。包含密钥的备份属于敏感材料，限制访问或加密，不放进公开 Git 仓库。

同一机器上的备份不能应对整机丢失。根据需要保存到自己的受保护存储，并明确保留和恢复策略。

## 恢复顺序

1. 判断配置和持久化状态是否仍存在。
2. 恢复程序依赖、文件权限和服务配置。
3. 检查是否已有实例运行。
4. 使用保存的接收进度和队列启动。
5. 检查任务是否曾执行，避免重复提交。
6. 发送无副作用测试，检查回传。

无法确认任务结果时，保留“未知”状态供管理员核对，不直接重跑高影响操作。

云端环境更新和重建是否保留文件，应以平台当前实际规则为准，不把个别部署经验写成永久保证。
