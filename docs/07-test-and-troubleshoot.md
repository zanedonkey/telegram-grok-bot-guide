## 第九步：逐项验收

先发送：
> 你好，请回复“连接测试成功”，不要执行其他操作。

再用一个简单、无副作用任务验证助手确实处理任务。

| 检查项 | 成功证据 | 初始状态 |
| --- | --- | --- |
| Token | getMe 成功 | 待实测 |
| 身份绑定 | 可信入口确认并保存 | 待实测 |
| 消息接收 | 已脱敏的接收状态 | 待实测 |
| 入口触发 | Routine 运行记录 | 待实测 |
| 执行结果 | 对应任务结果 | 待实测 |
| 回传 | 发送成功结果及实际私聊回复 | 待实测 |
| 未授权访问 | 第二账号无法触发任务 | 待实测 |
| 群消息限制 | 群输入无法触发任务 | 待实测 |
| 重复输入 | 相同更新按既定策略去重 | 待实测 |
| 重启恢复 | 保存进度与任务状态生效 | 待实测 |
| 失败处理 | 故障状态、恢复路径明确 | 待实测 |

只有实际观察到结果后才更改状态。没有第二账号就保留未实测；程序逻辑检查不能替代真实访问测试。

## 常见问题

| 表现 | 排查方向 |
| --- | --- |
| 401 | 确认是哪一服务报错，分别检查 Token 或入口鉴权 |
| 409 | 检查重复轮询实例及是否存在 Telegram 入站 Webhook |
| 429 | 按服务返回的限流信息等待，避免立即重试 |
| 请求超时 | 检查网络，区分未提交与提交结果未知 |
| 入口接受但没回复 | 检查 Routine 执行记录、回传路径和发送状态 |
| 重启后重复任务 | 检查持久进度、队列和下游去重 |
| 任意用户都能触发 | 立即停用入口，检查程序身份门闸 |
| 日志含密钥 | 停止分享日志，轮换受影响凭据并修复脱敏 |

长轮询与 Telegram 入站 Webhook 的关系见 [getUpdates 官方说明](https://core.telegram.org/bots/api#getupdates)。切换模式前确认影响，不默认丢弃待处理更新。

## 结果记录模板

```text
部署环境：<通用环境类型>
已实测：<项目和证据类型，不贴真实标识或密钥>
已实现但未实测：<项目>
尚未完成：<项目>
已知限制：<限制>
恢复方法：<本环境中实际存在的操作>
```

提交问题时只提供错误类别、脱敏描述和必要版本信息，不上传原始日志或配置。参见 [隐私说明](../PRIVACY.md)。
